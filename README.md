# 1. Что такое DNS

DNS — Domain Name System, система доменных имён.

Компьютеры связываются друг с другом по IP-адресам.

Например:

~~~text
192.168.10.20
~~~

Но человеку удобнее использовать имя:

~~~text
site.pgk.test
~~~

DNS связывает эти две вещи:

~~~text
site.pgk.test
       │
       │ DNS
       ▼
192.168.10.20
~~~

Можно представить DNS как телефонную книгу:

~~~text
Имя → нужный адрес
~~~

DNS не передаёт сам сайт, файл или сообщение.

Его задача — **сообщить клиенту, какой IP-адрес соответствует имени**.

После этого клиент уже самостоятельно обращается к найденному IP-адресу.

---

# 2. Что происходит при обращении к сайту

Представим, что пользователь вводит:

~~~text
portal.pgk.test
~~~

Компьютеру нужен IP-адрес.

Поэтому сначала выполняется DNS-запрос:

~~~text
Клиент
  │
  │ Какой IP у portal.pgk.test?
  ▼
DNS-сервер
  │
  │ Ответ
  ▼
192.168.10.30
~~~

Только после этого клиент подключается:

~~~text
Клиент → 192.168.10.30
~~~

Поэтому DNS и сам сайт — это разные вещи.

Возможна ситуация:

~~~text
ping 192.168.10.30 → работает
portal.pgk.test     → не открывается
~~~

В таком случае сеть может быть исправна, а проблема находится именно в DNS.

---

# 3. Доменное имя

Рассмотрим имя:

~~~text
student.portal.pgk.test
~~~

Оно состоит из нескольких частей:

~~~text
student . portal . pgk . test
   │         │       │     │
   │         │       │     └─ доменная зона верхнего уровня
   │         │       └─────── домен
   │         └─────────────── поддомен
   └───────────────────────── имя узла
~~~

Полное доменное имя называют **FQDN** — Fully Qualified Domain Name.

Например:

~~~text
dns.pgk.test.
~~~

Точка в самом конце показывает, что имя записано полностью.

В обычной речи и браузере последнюю точку обычно не пишут:

~~~text
dns.pgk.test
~~~

---

# 4. DNS-зона

DNS-сервер обычно отвечает не за весь интернет, а за определённую зону.

Например:

~~~text
pgk.test
~~~

Внутри неё могут существовать имена:

~~~text
www.pgk.test
mail.pgk.test
db.pgk.test
dns.pgk.test
student.pgk.test
~~~

DNS-сервер, который хранит правильные записи своей зоны, называют **авторитетным DNS-сервером**.

Например:

~~~text
Зона: pgk.test

dns.pgk.test     → 192.168.10.2
www.pgk.test     → 192.168.10.10
mail.pgk.test    → 192.168.10.20
~~~

---

# 5. Основные DNS-записи

## A — IPv4-адрес

Запись A связывает имя с IPv4-адресом.

~~~text
www.pgk.test    A    192.168.10.10
~~~

Означает:

~~~text
www.pgk.test → 192.168.10.10
~~~

---

## AAAA — IPv6-адрес

Запись AAAA делает то же самое для IPv6.

~~~text
www.pgk.test    AAAA    2001:db8::10
~~~

---

## CNAME — псевдоним

CNAME говорит, что одно имя является псевдонимом другого.

~~~text
portal.pgk.test    CNAME    www.pgk.test
~~~

Если известно:

~~~text
www.pgk.test    A    192.168.10.10
~~~

то:

~~~text
portal.pgk.test
        ↓
www.pgk.test
        ↓
192.168.10.10
~~~

CNAME обычно используют, когда несколько имён должны ссылаться на один и тот же узел.

---

## MX — почтовый сервер

MX указывает, какой сервер принимает электронную почту для домена.

~~~text
pgk.test    MX    10 mail.pgk.test
~~~

Число `10` — приоритет почтового сервера. Если MX-записей несколько, меньший приоритет используется раньше.

А сам почтовый сервер должен иметь IP:

~~~text
mail.pgk.test    A    192.168.10.20
~~~

---

## NS — DNS-сервер зоны

NS показывает, какой DNS-сервер отвечает за зону.

~~~text
pgk.test    NS    dns.pgk.test
~~~

И сам DNS-сервер должен иметь адрес:

~~~text
dns.pgk.test    A    192.168.10.2
~~~

---

## PTR — обратное разрешение

Обычный DNS-запрос:

~~~text
Имя → IP
~~~

Например:

~~~text
server.pgk.test → 192.168.10.50
~~~

PTR используется в обратную сторону:

~~~text
IP → Имя
~~~

Например:

~~~text
192.168.10.50 → server.pgk.test
~~~

---

# 6. DNS-кэш и TTL

Чтобы не выполнять один и тот же запрос постоянно, DNS-ответы можно временно хранить в кэше.

Например:

~~~text
Первый запрос:
client → DNS → www.pgk.test → 192.168.10.10

Следующий запрос:
client → кэш → 192.168.10.10
~~~

Сколько времени запись можно хранить, определяет параметр **TTL**.

TTL — Time To Live.

Например:

~~~text
TTL = 300
~~~

означает, что запись можно хранить в кэше 300 секунд.

Пока TTL не закончился, клиент или DNS-сервер может использовать уже сохранённый ответ.

---

# 7. Как проходит запрос к внешнему домену

Если локальный DNS-сервер не знает ответ, он может получить его у другого DNS-сервера.

Упрощённая схема:

~~~text
Клиент
  │
  │ Какой IP у example.com?
  ▼
Локальный DNS
  │
  │ Сам не знает
  ▼
Внешний DNS
  │
  │ Ответ
  ▼
Локальный DNS
  │
  ▼
Клиент
~~~

Поэтому один DNS-сервер может одновременно:

- самостоятельно отвечать за локальную зону;
- получать ответы для внешних доменов;
- кэшировать полученные ответы.

# Что нужно понимать после выполнения

- DNS связывает доменные имена с IP-адресами.
- DNS-запрос происходит до подключения к серверу по имени.
- A-запись хранит IPv4-адрес.
- AAAA-запись хранит IPv6-адрес.
- CNAME создаёт псевдоним другого имени.
- MX указывает почтовый сервер.
- NS указывает DNS-сервер зоны.
- PTR используется для обратного разрешения IP в имя.
- DNS-зона — часть пространства имён, за которую отвечает DNS-сервер.
- TTL определяет время хранения записи в кэше.
- Из-за кэша изменение DNS может стать заметно не сразу.
- Если соединение по IP работает, а по имени нет, одной из первых нужно проверять DNS.
- Несколько имён могут вести на один сервер.
- DNS-сервер и сервер, на котором работает сайт, — не одно и то же.
